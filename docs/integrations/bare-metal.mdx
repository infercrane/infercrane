# Existing bare-metal GPUs

For a server the control plane cannot reach (behind NAT, on loopback, or in a private network),
run the outbound-only [InferCrane agent](/architecture/agent) on the GPU host. It needs no inbound
port and keeps prompts on the machine:

```bash
infercrane agent run
```

See [Run on this machine](/run-on-this-machine). InferCrane does not take over a bare-metal
scheduler, and the agent does not start, stop, or change your server.

The CLI can also perform a bounded, read-only inventory of the machine where it runs:

```bash
infercrane discover local
```

Machine-readable output is available for setup scripts:

```bash
infercrane discover local --output json
```

The v1 probe invokes `nvidia-smi` directly without a shell and records concrete GPU index, UUID,
model name, total memory, and driver version. It has a five-second deadline, bounded output, and a
256-GPU limit. It does not inspect prompt data, install software, open a port, change GPU state, or
send inventory to the control plane.

<Warning>
  Hardware discovery is not compatibility or performance evidence. GPU presence does not prove
  model fit, runtime/CUDA compatibility, network reachability, health, cost, or a production SLO.
  `discover local` reads NVIDIA GPUs only. `infercrane agent detect` also reports Apple Silicon and
  AMD GPUs as detected, with their telemetry unknown.
</Warning>

## Connect the runtime already serving the host

Start or retain vLLM, SGLang, LiteLLM, or another OpenAI-compatible runtime under your existing
process manager. When the control plane can reach the host, connect the service directly without
transferring lifecycle ownership:

```bash
infercrane connect http://gpu-host.internal:8000/v1 --as support-production
```

If the server requires an API key, pass the name of an environment variable that holds it with
`--token-env VLLM_API_KEY`. The control plane stores the key encrypted and uses it for discovery and
health checks; that needs `INFERCRANE_CREDENTIAL_ENCRYPTION_KEY` on the control plane. Otherwise use
the agent, which keeps the key on the host.

The connection begins `observe-only`. InferCrane may discover the served model and record health,
but it does not SSH to the host, restart the process, change GPU allocation, scale replicas, or
delete the external service. Explicitly move to `traffic-managed` only after reviewing the route and
credential boundary.

Use a lifecycle provider adapter only when you want InferCrane to create and delete capacity.
Running candidate setups on your own GPUs will go through the agent, only for an engine the agent
launched itself; see [candidate runs](/architecture/agent#candidate-runs-next-slice). Read-only
discovery does not imply that capability.
