# ADR 0025: Fenced HA and protocol overlap

## Context

InferCrane must survive API and operation-worker loss, permit adjacent-version rolling upgrades, and
restore from PostgreSQL without duplicating provider mutations. PostgreSQL is already the durable
source of truth and operation leases already fence mutation ownership.

## Decision

Run stateless control-plane replicas against one highly available PostgreSQL database. Each replica
registers a stable instance ID, binary version, supported protocol interval, and heartbeat. Startup
fails closed when its interval does not overlap every live member. Membership is observability and
upgrade admission—not leader election. Operation workers continue to claim expiring leases and every
checkpoint or completion is fenced by the claim token.

Migrations remain forward-only, checksummed, transactional, and serialized by a PostgreSQL advisory
lock. Backup and restore are explicit operator actions: restore requires an approval flag, an exact
target database name, an empty live-membership set, archive validation, and post-restore migration
verification. TLS 1.3 is used when native TLS is configured; a client CA enables mandatory mTLS.

## Consequences

- Loss of an API replica does not affect durable state or make another replica wait for election.
- Expired operation work can resume, while a stale worker cannot checkpoint or finish it.
- Adjacent binaries may overlap only when their declared control protocol ranges intersect.
- Database availability remains an operator-owned dependency; InferCrane does not implement consensus.
- Certificate rotation is a rolling restart using overlapping trust bundles, not an in-process secret watcher.
- Schema rollback requires restoring the verified pre-upgrade backup.

## Alternatives

A custom leader election or distributed database would duplicate PostgreSQL and increase failure
surface. Permitting arbitrary mixed versions would make compatibility implicit. Automatically
restoring over the configured production database would turn a recovery tool into a destructive API.

## Verification

`scripts/test-ha-control-plane.sh` starts two control planes, removes one, and proves the survivor is
ready. Store tests cover protocol overlap and fenced lease recovery. `scripts/test-backup-restore-docker.sh`
uses real PostgreSQL tools to back up, restore into a distinct database, compare migration ledgers,
and start a restored control plane. CLI/server tests exercise TLS 1.3 and mandatory client identity.
