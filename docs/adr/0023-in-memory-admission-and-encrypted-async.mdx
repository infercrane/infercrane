# ADR 0023 — In-memory admission and encrypted durable async inference

Status: accepted

## Decision

PostgreSQL owns admission policy and async-job truth. Gateways periodically publish admission
policies into an in-memory snapshot; request acquisition performs no I/O. Async inference persists
only AES-256-GCM ciphertext and uses leased, token-fenced claims. Execution re-enters the normal
gateway rather than duplicating authentication, routing, admission, protocol or telemetry logic.

## Consequences

- A database outage cannot add synchronous latency to an already-running inference request path.
- A policy update converges within the refresh interval rather than atomically across every gateway.
- Live admission pressure is reported as an explicitly instance-local snapshot; saturation does not
  change gateway liveness, database readiness, runtime health, or served-model identity.
- Request IDs are assigned before admission. Queue wait is part of end-to-end request latency and
  overload outcomes persist content-free evidence with a bounded retry hint.
- Control-plane restart and worker loss do not lose queued work.
- Duplicate submissions converge by tenant-scoped idempotency key.
- Prompt/result retention is explicit and encrypted; synchronous requests remain content-free by
  default.
- This primitive cannot express task graphs, fan-out, arbitrary code or general workflows.

Retries are permitted only for buffered InferCrane-managed requests before response delivery.
Streaming and external paid capacity are excluded to prevent duplicate output and unbounded spend.
