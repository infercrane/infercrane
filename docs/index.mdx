InferCrane refuses speedups that change your answers. It runs beside the vLLM or SGLang servers you
already have, on a laptop, a Kubernetes cluster or a cloud account, and prompts and answers stay in
your account.

## Every change proven before it ships

<Steps>
  <Step title="Measured against your current setup">
    Setups take turns under the same traffic, and a copy of your current setup is measured the same
    way, so the run knows its own noise instead of assuming it. When setups run on separate servers,
    every comparison also carries an allowance for the difference between machines.
  </Step>
  <Step title="Again on fresh servers">
    A gain counts only when it holds on machines that didn't produce it.
  </Step>
  <Step title="Answers checked">
    The candidate answers a graded task set. A setup that changes answers must hold within 1 point,
    or it is refused, however fast it is.
  </Step>
  <Step title="Rolled out with a fallback">
    A second server takes traffic first, your current server stays up as the fallback, and traffic
    switches back automatically if the guard sees a regression.
  </Step>
</Steps>

A result the evidence doesn't show is reported as "not shown", never as a win. See
[how a run measures and confirms a gain](/features/optimization) and
[how answers are checked](/features/semantic-quality).

## Results and receipts

Each result links to its receipt: the rules written before the run, the machines, and every server's
results.

| Result | Status |
|---|---|

One model, one GPU type, chat traffic; read [the disclosures](/features/trained-drafts). | Lab-proven, coming to InferCrane |
| On an NVIDIA L4 at 32 requests at once, both drafts were **slower** than no speculation, so speculation stays off there. ([receipt](/features/trained-drafts)) | Measured |
| The publisher's documented speculation setting served **32.1% more output** on Qwen3.8-27B FP8 at 32 requests at once on one H100, and **33.1% more** on two fresh servers; p95 time to first token was 31.4% worse on the fresh servers. ([receipt](/testing/qwen38-27b-fp8-h100-campaign-2026-11-23)) | Measured; proposed, not activated |
| FP8 weights with an FP8 KV cache served **62% to 159% more output** on Qwen3-8B on an NVIDIA L4, but lost 1.10 points on 1,000 graded tasks, so the change was **refused**. ([receipt](/testing/qwen3-8b-fp8-l4-confirmation-2026-11-26); [published FP8 checkpoints](/testing/qwen3-8b-fp8-checkpoints-l4-2026-11-26)) | Refused |

InferCrane doesn't replace your engine. It runs [vLLM](https://github.com/vllm-project/vllm) and
[SGLang](https://github.com/sgl-project/sglang) as they are, drives load with
[AIPerf](https://github.com/ai-dynamo/aiperf), and trains drafts with
[speculators](https://github.com/vllm-project/speculators).

<Note>
Each provider, runtime, model, and accelerator combination has its own qualification state. Review
[compatibility and qualification](/compatibility) before relying on an exact combination.
</Note>
