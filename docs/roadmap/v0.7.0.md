# v0.7.0 — inference decisions

## Outcome

InferCrane recommends and explains deployment choices from qualified evidence and enforces explicit
SLO, overflow, privacy and cost policy.

## Scope

- recommendation records with provenance, confidence and missing-data disclosure
- model/runtime/GPU/provider/region compatibility and capacity intelligence
- deterministic SLO policy for latency, error, availability and bounded cost signals
- health/queue-driven hybrid overflow to approved external targets
- explanation and audit output for every recommendation and routing change

## Product contract

`infercrane recommend DEPLOYMENT` evaluates persisted AIPerf runs for that deployment against the
deployment's persisted SLO policy. It returns one of `recommended`, `no_match`, or `unknown` and
persists the complete input snapshot, algorithm version, selected benchmark identity, rejected
candidates, missing fields, and reason. Repeating evaluation over the same ordered evidence and
policy produces the same result.

A recommendation is advisory in v0.7. It never changes a DeploymentSpec, substitutes a GPU, creates
capacity, or sends inference traffic. Cost constraints are evaluated only when cost metadata has a
source and observation timestamp. Missing price, capacity, latency, throughput, compatibility, or
availability remains `unknown`.

SLO policy uses normalized p95 TTFT, p95 request latency, request error rate, output-token
throughput, and trustworthy hourly cost. Every configured threshold is fail-closed: a candidate
missing its required signal is ineligible rather than treated as zero.

Hybrid overflow remains an explicit external-target policy. Health-based overflow is permitted only
after primary capacity is unavailable. Queue-based overflow additionally requires a bounded queue
threshold, consecutive breach/recovery observations, cooldown, privacy acknowledgement, compatible
model mapping, and an available hard request/cost lease. Routing changes are persisted as decisions;
the gateway never reads PostgreSQL and never replays or silently duplicates a request.

## Exclusions

No fabricated price/capacity data, autonomous `provider:auto`, semantic routing, silent request
duplication, or model-quality judgment by an LLM.

## Acceptance

### Recommendation and capacity evidence

- recommendations reproduce byte-for-byte from a canonical persisted input snapshot;
- evidence is tenant-scoped and references immutable benchmark and model-artifact identities;
- provider/runtime/mode compatibility is checked against the exact support matrix;
- unqualified combinations, stale/unknown capacity, and unavailable prices are disclosed;
- rankings are deterministic and use only measured values requested by policy;
- API, CLI, OpenAPI, SDK and dashboard surfaces preserve status, provenance and missing evidence.

### SLO and overflow policy

- invalid, empty, negative, or unbounded policies are rejected before persistence;
- missing required metrics fail closed and no cost is synthesized;
- queue breach and recovery use consecutive observations plus cooldown to prevent oscillation;
- privacy denial, model mismatch, health recovery, budget exhaustion and stale queue evidence keep or
  restore primary routing deterministically;
- every overflow selection or denial is persisted and reproducible;
- streaming cancellation remains one attempt with no replay or hidden duplication.

### Qualification

- unit simulations cover recommendation ordering, ties, missing signals, SLO violations, oscillation,
  budget exhaustion, provider recovery, privacy denial and fail-closed behavior;
- PostgreSQL migration/upgrade tests prove durable policy and decision isolation;
- control API, CLI, generated OpenAPI, Python/TypeScript SDKs, Terraform and dashboard contracts are
  exercised locally and in Docker;
- all v0.2-v0.6 regression and release gates pass on the exact clean commit;
- paid price, capacity, AWS and RunPod evidence remains `DEFERRED` until consolidated v1 qualification.
