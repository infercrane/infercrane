# v1.3.0 — capability-qualified inference protocols

## User outcome

Applications keep a stable InferCrane model identity across Chat Completions, Completions,
Embeddings, Responses, and bounded online chat batch while runtime-specific behavior remains
explicit and inspectable.

## Ownership

InferCrane owns authentication, endpoint selection, model alias rewrite, generation pinning,
admission hooks, normalized metadata and capability enforcement. The runtime owns protocol parsing,
generation/embedding behavior, native errors and response schemas.

## Acceptance

- each protocol is gated independently from the immutable in-memory route snapshot;
- unknown and unsupported capabilities fail before network transmission;
- request fields and native responses are byte-semantically preserved except for logical model
  identity rewrite and controlled upstream authentication;
- cancellation, streaming, external budgets, quotas and no-replay behavior remain shared;
- protocol identity persists in content-free request telemetry;
- current pinned runtime limitations remain explicit in registry and docs;
- OpenAPI, Docker fixtures, SDK generation, docs and all earlier gates pass.

## Exclusions

No universal inference schema, automatic runtime upgrade, fabricated model-task compatibility,
audio protocol, stored Responses lifecycle, offline file service, workflow engine, or paid-resource
qualification.
