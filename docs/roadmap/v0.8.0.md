# v0.8.0 — release evidence

## Outcome

Every revision can prove what it is, how it was validated, why it was promoted, and how to reproduce
it.

## Scope

- Release Guard V2 compatibility, synthetic, performance, error and cost policies
- bounded explicit canary support and deterministic automated rollback
- consent and cost disclosure for any duplicated validation traffic
- signed, reproducible Inference Passport with artifact, image, runtime, provider, configuration,
  benchmark, cold start, policy and qualification identities
- GitHub release checks

## Exclusions

No LLM promotion decision, silent shadow traffic, model-output retention by default, or unsupported
cryptographic/compliance claim.

## Acceptance

- Policy migration is forward-only, bounded, tenant-safe, and preserves v1 defaults.
- Explicit validation uses AIPerf, requires cost acknowledgement, obeys persisted request/concurrency
  bounds, retains no model content, and never duplicates production requests.
- Compatibility compares immutable model identity, runtime, runtime version, compute mode, tool
  version, and workload. Configured sourced cost policy waits when evidence is unavailable.
- The post-promotion monitor and deadline are persisted. Previous healthy capacity remains retained;
  rejection atomically restores its target set before failed capacity is drained and deleted.
- Passports are canonical, byte-preserving, verifiable, tenant-safe, and secret-free. Payload,
  signature, digest, public-key, or key-ID tampering fails verification.
- CLI, API, generated SDKs, dashboard, Mintlify docs, and GitHub release checks expose the same
  evidence identities. GitHub checks require a complete, verified passport and record its digest.
- Full race, PostgreSQL migration, Docker stack/failure, automation, docs, audit, dead-code, release,
  contract, and clean-tree qualification gates pass without paid resources.
