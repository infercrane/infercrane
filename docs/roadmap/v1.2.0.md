# v1.2.0 — adopt, inspect and diagnose

## User outcome

Teams connect an existing OpenAI-compatible workload without replacing it. They can begin in
read-only observation, explicitly allow InferCrane to manage traffic later, inspect a request by ID,
and receive deterministic findings and signed alerts from persisted evidence.

## Ownership ladder

```text
observe-only → traffic-managed → lifecycle-managed
```

- `observe-only` health-checks and records evidence but never publishes a route or mutates the
  imported workload.
- `traffic-managed` may publish the existing target behind an InferCrane endpoint but never creates,
  scales, updates, or deletes the workload.
- `lifecycle-managed` remains reserved for workloads whose provider lifecycle is owned by an
  InferCrane deployment; adoption never silently escalates into it.

## Public surface

- `infercrane adopt endpoint NAME --url URL --model MODEL --ownership observe-only|traffic-managed`
- `infercrane request inspect REQUEST_ID`
- `infercrane doctor ENDPOINT`
- alert policy and delivery APIs/CLI using generic signed webhooks and secret references

## Determinism and privacy

Request inspection returns routing identity, timings, token counts, retry/fallback metadata, status,
and error class. Prompt, output, authorization values, and resolved signing secrets are neither
stored nor returned. Doctor findings are `Evidence → Rule → Finding`; an LLM does not create causes.
Webhook bodies are canonical JSON, signed with a referenced secret, idempotent by finding/policy,
bounded, and delivery attempts are auditable.

## Acceptance

- adoption is transactional, tenant-isolated and idempotent;
- observe-only bindings never enter a route generation and delete never touches the imported target;
- traffic-managed bindings compile from healthy targets into the in-memory directory;
- request inspection is tenant-scoped and proves content exclusion;
- Doctor findings are reproducible from request metrics, endpoint state and persisted events;
- webhook signatures, retry bounds, delivery idempotency, SSRF policy and secret redaction pass tests;
- OpenAPI, CLI, generated SDKs, Mintlify docs, migrations, Docker and all earlier gates pass.

## Exclusions

No target replacement, credential ingestion, arbitrary plugin execution, autonomous remediation,
prompt capture, workflow engine, paid-provider qualification, or silent external request replay.
