# v0.2.0 — integration contracts

## Outcome

Adding a provider or runtime does not require provider/runtime conditionals in lifecycle core, and
support claims are backed by durable machine-readable qualification evidence.

## Scope

- versioned Provider Contract V1 and Runtime Contract V1
- explicit capability declarations for elastic, serverless, and governed external targets
- registries that separate adapter identity, capability, and qualified support
- deterministic provider/runtime conformance harnesses and fault injection
- replay-safe create/adopt/observe/cancel/delete/orphan scenarios
- durable sanitized qualification records tied to commit, adapter and contract version
- CLI/API inspection of registered versus qualified capabilities

## Exclusions

No AWS, new runtime, dynamic plugin loading, paid-provider execution, general router, or marketplace.

## Acceptance

- existing RunPod/SkyPilot/vLLM behavior composes through the contracts
- a hermetic second adapter proves core code remains provider-neutral
- conformance detects lost create responses, duplicate intent, partial delete, timeouts and redaction
- runtime conformance covers readiness, protocol, streaming, cancellation, drain and telemetry
- docs distinguish registered, simulated, locally qualified and real-infrastructure qualified
- all gates in `.release/gates.yaml` pass; real infrastructure is recorded `DEFERRED`
