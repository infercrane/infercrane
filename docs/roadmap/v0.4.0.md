# v0.4.0 — automation interfaces

## Outcome

Applications and delivery systems use the same durable control-plane semantics as the CLI.

## Scope

- generated, ergonomic Python and TypeScript SDKs
- synchronous and asynchronous operation helpers, streaming and typed errors
- Terraform provider with explicit desired-state versus asynchronous-operation semantics
- GitHub Action for semantic plan and release checks
- pull-request output suitable for environment promotion

## Exclusions

No lifecycle logic in SDKs, no prompt framework, no implicit apply from a plan, and no Terraform
ownership of provider resources beneath InferCrane.

## Acceptance

### Contract

- An executable OpenAPI 3.1 document describes every public `/api/v1` route, authentication,
  idempotency headers, durable operations, typed errors, and server-sent inference streams.
- Route registration and OpenAPI operation coverage are compared in CI; generated artifacts are
  deterministic and a dirty regeneration fails `make verify`.
- SDKs, Terraform, the CLI, and GitHub automation call the control-plane API only. They never own
  provider resources or query PostgreSQL directly.

### Python and TypeScript

- Checked-in Python and TypeScript packages are generated from the same OpenAPI identity and expose
  typed low-level API methods plus small handwritten ergonomic clients.
- Both clients support explicit idempotency keys, request timeouts, typed API errors, operation
  lookup/cancellation, synchronous wait helpers, native asynchronous wait helpers, and OpenAI SSE
  streaming without replaying a request.
- Packaging metadata, version identity, README examples, and tests are included. Smoke examples run
  against the local Docker stack; hermetic tests prove disconnect, timeout, terminal failure, and
  malformed-stream behavior.

### Terraform

- A real Terraform Plugin Framework provider manages logical InferCrane deployments through the
  control-plane API. Desired state contains only user intent; provider-owned replica IDs and
  infrastructure details are read-only observations.
- Create, update, and delete submit an idempotent operation and poll it to a terminal state. A client
  timeout returns diagnostics without cancelling the durable operation; the next refresh or apply
  adopts the same logical deployment.
- Read detects remote deletion, import uses the deployment name, sensitive credentials are accepted
  only through provider configuration/environment, and plan modifiers prevent accidental identity
  replacement.
- Unit, protocol, CRUD, import, interrupted-apply, and redaction tests run without paid resources.

### GitHub delivery

- A versioned JavaScript action installs or uses a pinned InferCrane CLI and emits a semantic plan as
  deterministic Markdown plus machine-readable JSON.
- Pull-request mode is read-only. Apply requires an explicit input and environment authorization;
  no plan can implicitly mutate capacity.
- Release checks verify an exact deployment/revision and persist evidence suitable for protected
  environments. Logs and summaries redact API keys and provider credentials.
- Fixture tests prove stable ordering, no ANSI output, bounded summaries, secret safety, and accurate
  success/failure exit codes.

### Milestone gate

SDK examples execute against the local stack; OpenAPI drift, Terraform lifecycle behavior, GitHub
output, package builds, documentation links, security checks, previous milestone regressions, and
the complete Docker qualification pass. Paid provider qualification remains explicitly deferred to
the consolidated v1.0 manual run.
