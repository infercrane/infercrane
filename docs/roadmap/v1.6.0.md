# v1.6.0 — Recoverable control plane

## Outcome

Qualify stateless multi-replica operation, fenced failover, adjacent-version admission, guarded
backup/restore, and TLS identity without changing provider or runtime ownership boundaries.

## Acceptance

- Two API replicas share PostgreSQL and one remains ready after the other stops.
- Expired durable work is reclaimable and stale lease holders cannot mutate operation state.
- Live control-plane membership exposes binary and protocol evidence through API, CLI, and SDKs.
- Compatible protocol intervals overlap; incompatible live binaries fail startup.
- TLS is TLS 1.3 or newer and optional client-CA configuration enforces mTLS.
- Partial TLS identities fail closed; certificate rotation has an overlap-and-rolling-restart runbook.
- Backups are verified and checksummed; restore requires explicit approval and an exact, non-live target.
- A real local PostgreSQL drill starts a control plane from restored state and records measured duration.
- Every historical migration, API, SDK, Docker, security, docs, and prior milestone gate passes.

## Exclusions

No custom consensus, database clustering, certificate authority, secret manager, service mesh, hosted
control plane, or claim that a local Docker drill qualifies a customer PostgreSQL topology.
