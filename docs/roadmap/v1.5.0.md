# v1.5.0 — Provider-product profiles

## Outcome

Prove the provider-neutral architecture with a second executable cloud while modeling AWS, GCP, and
CoreWeave products according to their real ownership boundaries.

## Acceptance

- Exact adapter identity persists through API, CLI, SDK, revision, restart, rollout, and reconciliation.
- Legacy unambiguous cloud/runtime selection remains compatible; ambiguity fails closed.
- GCP Compute create/observe/adopt/delete/inventory is deterministic, private, immutable, and uses an
  attached service account without static key material.
- AWS EC2 and GCP Compute expose independent local qualification evidence.
- AWS ASG/EKS/SageMaker/Bedrock, GCP MIG/GKE/Vertex, and CoreWeave CKS expose honest registered and
  deferred profiles without claiming executable or real qualification.
- Documentation, OpenAPI, SDKs, integration inventory, support matrix, and release evidence agree.
- All historical gates and local Docker qualification pass; real provider execution remains deferred.

## Exclusions

No cloud scheduler, provider-owned child-resource emulation, automatic provider selection, live
pricing claims, public networking shortcut, stored cloud keys, or paid infrastructure execution.
