# v0.3.0 — secure BYOC and governed external capacity

## Outcome

Teams can operate a narrow AWS BYOC deployment and explicitly use external OpenAI-compatible
capacity without losing tenant isolation, auditability, privacy control or budgets.

## Scope

- organizations/projects/environments only where the domain model requires them
- scoped service credentials, secret references, RBAC and audit foundation
- external OpenAI-compatible target contract and OpenRouter adapter
- explicit health fallback with privacy disclosure and hard request/cost limits
- AWS EC2 BYOC adapter: role assumption, VPC/network inputs, immutable image, tags, reconciliation,
  orphan discovery and trustworthy cost metadata

## Exclusions

No EKS, SageMaker-wide abstraction, billing marketplace, semantic/LLM routing, silent shadowing,
managed compute, or automatic unbounded fallback.

## Acceptance

Security boundaries have adversarial tests; external routing is opt-in and persisted; the AWS
adapter passes Provider Contract V1 hermetically. Real AWS and external billing acceptance remain
`DEFERRED` until final manual qualification.
