# v0.9.0 — Kubernetes and advanced topologies

## Outcome

Enterprise clusters can participate without making Kubernetes an InferCrane dependency.

## Scope

- a namespaced Kubernetes Provider Contract adapter using deterministic ownership labels, immutable
  OCI workloads, server-side apply, strict validation, and provider-native inspection
- standard `Deployment` plus cluster-local `Service` as the dependency-light core path
- optional standard-mode KServe `InferenceService` ownership when its CRD is installed; KServe owns
  generated children and InferCrane never competes with its controller
- an optional Gateway API `HTTPRoute` for exposing the InferCrane gateway, never for replacing
  revision routing
- read-only cluster capability discovery and explicit qualification state
- conditional Dynamo and llm-d topology boundaries when stable interfaces satisfy runtime ownership

## Exclusions

No Kubernetes distribution, Helm controller, new general scheduler/router, custom operator,
cluster-wide RBAC, KServe installation, Gateway implementation, or reimplementation of
KV/disaggregated inference.

## Acceptance

- Configuration fails closed on namespace, context, immutable image, service account, worker Secret,
  GPU resource/selector, and workload API mode.
- A durable replica intent adopts exactly one deterministic owner set after lost responses; partial
  owner sets reconcile without creating duplicate serving Pods.
- Every apply is first submitted as strict server-side dry-run, then applied with an explicit field
  manager and without forced conflict takeover.
- Observation exposes native kind/name/UID/generation/conditions and a cluster-local endpoint;
  provider details remain available without leaking Secret values or kubeconfig content.
- Delete verifies ownership before deleting exact names, is replay-safe, and inventory reports only
  explicitly owned resources, including partial/orphaned owner sets.
- A least-privilege namespaced RBAC manifest grants only the read/apply/delete verbs and resources the
  adapter uses. The control plane never reads Kubernetes Secret values.
- Kind tests cover strict dry-run, apply, adoption after lost response, restart observation, conflict,
  partial-resource repair, delete replay, and orphan inventory. Fake-kubectl contract tests cover
  failure injection and KServe CRD presence/absence deterministically.
- KServe support is limited to standard `InferenceService`; advanced `LLMInferenceService`, Dynamo,
  and llm-d remain registered/deferred because they own scheduling or routing that InferCrane must
  not duplicate.
- CLI/API, capability registry, doctor output, dashboard inspection, docs, release packaging, and
  generated evidence expose Kubernetes state without changing the provider-neutral primary path.
- Full local/Docker/Kind, migration, security, documentation, previous-milestone, and clean-tree
  qualification gates pass. Real customer clusters and GPUs remain deferred to the consolidated v1
  manual qualification.
