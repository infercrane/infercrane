# v0.9.0 — Kubernetes and advanced topologies

## Outcome

Enterprise clusters can participate without making Kubernetes an InferCrane dependency.

## Scope

- Kubernetes provider adapter using existing workload and identity mechanisms
- KServe and Gateway API integration where their contracts fit
- cluster capability discovery and provider-native inspection
- conditional Dynamo and llm-d topology adapters when stable interfaces satisfy runtime ownership

## Exclusions

No Kubernetes distribution, new general scheduler/router, custom operator unless an ADR proves
existing extension points insufficient, or reimplementation of KV/disaggregated inference.

## Acceptance

Kind/hermetic cluster tests cover apply/adopt/restart/delete/orphans; manifests are server-side
validated; RBAC is least privilege; Dynamo/llm-d remain conditional and cannot block the Kubernetes
core milestone if their stable contracts are unsuitable.
