# v0.5.0 — operational dashboard

## Outcome

Operators can understand fleet state and evidence without replacing code-first workflows.

## Scope

- responsive, accessible fleet and deployment views
- durable operations, revision history, rollout and Release Guard evidence
- scaling decisions, cold-start timelines and deterministic explanations
- benchmark history, provider resource inspection, cost signals and audit events
- carefully gated mutations that call the existing API where justified

## Exclusions

No billing UI, cloud resource manager, account signup product, workflow canvas, or duplicate backend.

## Acceptance

### Ownership and security

- The dashboard is a static client embedded in the release binary. It calls only authenticated
  public control-plane routes and contains no lifecycle logic, database client, provider
  credentials, analytics, external fonts, or third-party runtime assets.
- A credential is kept only in tab-scoped session storage, is never placed in a URL, cookie, log,
  DOM node, or persistent browser storage, and can be explicitly forgotten. Server-side RBAC
  remains authoritative.
- Static responses set a restrictive Content Security Policy, deny framing and MIME sniffing, use
  a same-origin referrer policy, and do not cache the application shell or credential-bearing API
  responses.

### Operator experience

- `/dashboard/` provides fleet summary and deployment drill-down for lifecycle, active operation,
  revisions, Release Guard, request/cold-start telemetry, benchmarks, scaling decisions, targets,
  replicas, provider artifacts, events, orphans, and permitted audit history.
- Loading, empty, disconnected, unauthorized, forbidden, partial-data, stale, reconnecting, and
  healthy states are visibly distinct. Historical failures cannot be mistaken for current health,
  and unknown cost or timing evidence is never rendered as zero.
- Refresh is reconnectable and preserves the selected deployment/view. Auto-refresh pauses in a
  hidden tab. A cooperative cancel action requires explicit confirmation, calls the existing
  durable API, and never implies that closing the page cancels work.
- The layout works at 360px, tablet, desktop, and wide screens without horizontal page scrolling;
  navigation, tables, long identifiers, and reduced-motion behavior have explicit fallbacks.

### Accessibility and validation

- The shell uses semantic landmarks, a skip link, labelled controls, keyboard-operable navigation,
  visible focus, non-color status text, an ARIA live connection state, and respects reduced motion
  and contrast preferences.
- Go handler tests verify routing and security headers. Deterministic JavaScript model tests verify
  API error classification, stale-state derivation, evidence formatting, safe text rendering, and
  cancellation guards. Structural accessibility and responsive-contract checks run in CI.
- The local Docker stack serves the real embedded dashboard and a smoke test authenticates through
  the same API used by the UI. Public docs include connection, investigation, cancellation,
  credential handling, and troubleshooting workflows.

### Milestone gate

Dashboard unit/security/structure tests, authenticated Docker smoke, prior terminal/CLI/API
regressions, documentation, dependency security, packaging, and complete local qualification pass.
Paid infrastructure remains deferred to the consolidated v1 manual run.
