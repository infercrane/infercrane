# v1.1.0 — stable endpoint identity

## User outcome

Applications address a stable endpoint without knowing which provider, runtime, deployment, or
external target currently realizes it. Operators can stage and inspect a candidate serving plan
without changing the application's model name.

## Domain

```text
LogicalModel + Environment
            ↓
         Endpoint
            ↓
       ServingPlan (immutable)
            ↓
      BackendBinding
            ↓
 Deployment or external target
```

- `LogicalModel` is the product-level workload identity.
- `Environment` owns the deployment context and bounded policy document.
- `Endpoint` is the stable OpenAI-compatible model name.
- `BackendBinding` refers to a concrete lifecycle-managed deployment or an external target without
  leaking provider/runtime concepts into the core identity model.
- `ServingPlan` is an immutable, content-addressed routing declaration. An endpoint may point to one
  active and one candidate plan.

## Compatibility

Migration creates a `production` environment, logical model, endpoint, lifecycle-managed binding,
and active serving plan for every existing non-deleted deployment. The endpoint name equals the
legacy deployment alias, so existing requests and CLI workflows continue to work. Deployments
remain concrete lifecycle resources and are not renamed or silently transferred.

## Initial routing policies

- `manual`: route only to the explicitly selected binding.
- `primary-fallback`: try ordered healthy bindings without replaying an accepted streaming request.
- `weighted`: select among healthy bindings using deterministic bounded weights.

Candidate plans receive no application traffic by default. Release Guard compares evidence attached
to active and candidate plans and persists `PASS`, `REJECT`, or `INCONCLUSIVE`.

## Acceptance

- forward-only migration and every-prefix upgrade tests preserve legacy aliases and tenant isolation;
- endpoint CRUD and plan activation are available through authenticated API, CLI and generated SDKs;
- immutable serving plans reject mutation and cross-tenant references;
- the reconciler compiles endpoint routes into memory and the gateway performs no database lookup;
- long-running streams remain pinned to their acquired route generation during promotion;
- request telemetry includes logical model, environment, endpoint, plan and binding identity;
- endpoint Release Guard is deterministic, persisted and auditable;
- docs, OpenAPI, generated clients, Docker integration and previous v1 regression gates pass.

## Exclusions

No dynamic plugin system, intelligent router, managed compute, autonomous promotion, prompt capture,
or paid-provider qualification. Import/adopt workflows begin in v1.2.
