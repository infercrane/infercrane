# Rules: rung 3, a small MoE end to end on one L40S, tuned against untuned (26 Nov 2026)

Written before any server of this rung started. A change means a new rules file. It runs only
if rung 2 (`rules-moe-shapes-l40s-2026-11-26.md`) asked for it: a projection of at least 1.02x
for this model at 32 or 128 at once.

## Question

Does rung 2's tuned set for vLLM 0.34.0's fused-MoE kernel on an L40S give Qwen3-30B-A3B more
output per second end to end than the same engine untuned, at the map's short chat with 32 and
with 128 requests at once, with answers as good, and are the answers the same?

## Setup (both arms identical except the tuned folder)

| | |
|---|---|
| Model | `Qwen/Qwen3-30B-A3B-Instruct-2507-FP8` at `5a5a776300a41aaa681dd7ff0106608ef2bc90db` (Apache-2.0, 31 GB; 128 experts, 8 per token, expert intermediate 768, hidden 2,048, FP8 in 128×128 blocks). Its MoE shape is the same as Qwen3-Coder-30B-A3B's |
| Engine | `vllm/vllm-openai@sha256:20fdb089454afbb324efa4110a2c025ff7b27cc1a086e07aa580b18df8ad1ce1` (v0.34.0) |
| Command | `vllm serve <weights> --served-model-name <model> --max-model-len 4096`. vLLM's recipe for Qwen3-30B-A3B has no base arguments; 4,096 tokens lets the KV cache fit beside 31 GB of weights on 48 GB and holds every request here |
| Candidate only | `VLLM_TUNED_CONFIG_FOLDER=/opt/infercrane/kernel-configs` holding rung 2's tuned file for `E=128,N=768,device_name=NVIDIA_L40S,dtype=fp8_w8a8,block_shape=[128,128]` (given with `--set`, checked against its digest) |
| GPU | Modal `L40S`, one, 8 cores, 48 GiB, `retries=0` |
| Plan | `KERNEL_TUNE_PLAN=qwen3-30b-a3b-l40s` |

## Steps

1. **Gap check (first machine).** One unmeasured start of the untuned engine. Its log must name
   the `TRITON` FP8 MoE backend and exactly the given set's file as the one it looked for and
   did not find. Otherwise the machine stops before measuring.
2. **Window (each machine).** Nine engine starts on the one GPU: control, candidate, …, control.
   Each measures `short/128` (prompt set v2, 128 at once) and `short/32` (v1, 32 at once): one
   user message, temperature 0, reasoning off, at most 295 tokens, streamed, warm-up 15 s,
   window 45 s, the load kept until the window's requests end (at most 20 s).
3. **Answers (first machine, starts 1–3).** The 1,000-item task set at 64 at once; then the 24
   prompts of v1's short "answers" slice **one at a time**, so batching cannot change an answer.
4. **Fresh machine** only if the first window shows a cell the judge calls improved and nothing
   it rejects. It serves the same set; no answers step.

Every start proves from its log that it read the tuned file (candidate) or used the engine's
default for it (control). A start with a failed request, or that does not fit before the cap,
ends the window.

## Judging

`infercrane optimize evidence kernel-tuning --file window-first.json --fresh window-fresh.json --set kernel-configs.json`,
as in the H100 rules: per cell, the campaign's paired comparison with its 0.75% machine
allowance at confidence 1 − 0.05/2, adjacent control drift at most 15%; confirmed only when
the fresh machine agrees; reject on any regressed cell or a worse task score; propose when a
cell is confirmed and the task set shows no measurable difference.

**Answers one at a time** (`changes_answers`):
- `no`: the tuned start gave the same text as the control on all 24 prompts, and two control
  starts gave the same text as each other. The technique records `ChangesAnswers: false`.
- `yes`: the controls agreed and the tuned start did not. Recorded `ChangesAnswers: true`: the
  KL gate applies before the technique ships, whatever the speed result.
- `unknown`: the two control starts already differ, so the engine is not deterministic here.

## What counts as a result

- A gain is claimed only when the decision is `propose`, at the loads where it was confirmed,
  with the paired delta and its interval. Anything else is reported as "not shown", including
  a gain inside the noise.
- The measured MoE share (`amdahl.py measured` on this window) is reported beside rung 1's
  estimate.
- Nothing here says anything about an H100 or another model.
